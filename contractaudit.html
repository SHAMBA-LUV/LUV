How the audit was actually conducted

Method, stated so the result can be weighed rather than trusted: four parallel deep-audit passes over the token, distributor, locker and periphery, each required to back a claim with a proof-of-concept against an isolated copy; slither static analysis (99 results, headline detectors triaged); and live-state verification on chain of every finding claimed to affect a deployed contract — because a finding that is true of the source and false of the deployment is not a finding.

That last step matters both ways. It demoted at least one high-severity item to moot against the live configuration, and it confirmed others as real. Severity here reflects real-world impact after that check, not textbook classification.

Standing instruction

Withdrawal is mitigation, not remediation. Removing a document from the default branch does not remove it from git history, from forks, or from anything that already mirrored it — and it changes nothing on chain. Assume the withdrawn contents are known. The only durable fix is to change the state of the contracts themselves.

The act-now items, the ordering, and the calldata are in the withdrawn runbook. Execute from there, over an authenticated channel — not from this page.
